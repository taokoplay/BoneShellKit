# BoneShellKit Demo 与测试方案

状态：研发规划。已建立基础 SDK、Demo 与自动化测试；本文的 13 个场景和 30 个用例定义完整目标范围，不表示全部验收已完成。已执行子集与真机安装结果见 [验证记录](Implementation-Status.md)。

## 1. Demo 工程要求

Demo 是可在模拟器和真机运行的 UIKit Universal App，项目名为 `BoneShellDemo`，位于 `Examples/BoneShellDemo/`。从 SDK 0.1 开始同步建设，后续每项能力都增加可操作的示例与对应测试。

- 以本地相对路径 `../..` 引用根目录 Swift Package；使用 SDK 公开接口，避免在 Demo 中复制实现或另写一套导航布局。
- Demo App 最低支持 iOS 15，开启 iPhone 与 iPad 设备族；采用与 SDK 相同的新编译工具链，通过 availability 分支使用新系统能力。
- 提供共享 Scheme `BoneShellDemo`，包含 App、集成测试、UI 测试及测试计划；首次运行不依赖网络、账号或后端。
- 使用固定示例数据、稳定的页面 / 操作 / 标签 ID；测试启动参数可选择场景和初始配置，不改变系统真实版本或绕过 SDK 能力检查。
- 首页提供场景目录与恢复默认配置。调试区显示请求配置、实际渲染器、实际材质及降级原因，便于确认设置是否生效。
- 页面级样式调整直接更新可支持的表面；渲染器变更通过容器级安全切换入口执行，不在 push / pop 或交互返回过程中直接替换。

## 2. 可交互场景

| ID | 场景 | 操作与观察点 |
| --- | --- | --- |
| D01 | 最小接入 | 继承基类，设置标题和操作，构建普通内容；展示业务页面无需计算栏高的接入方式 |
| D02 | 导航栏与多按钮 | 左右各 0–8 个按钮、长标题、大标题、副标题、分组、菜单、badge、加载 / 禁用状态；观察溢出及标题避让 |
| D03 | 标签与独立导航栈 | 多个标签、各标签 push 多层、系统 / 浮动 / 可用时侧边栏展示、附加创建入口；切换后保留当前位置 |
| D04 | 列表详情自适应 | 选中详情并编辑，调整窗口宽度或切换支持的设备姿态；观察双栏展开 / 折叠、选中项与返回路径 |
| D05 | 材质对照 | 自动 / 系统 / 自定义渲染器，高版本玻璃 / 经典、低版本默认 / 仿玻璃；展示实际结果和不支持组合的降级 |
| D06 | 安全区与键盘 | 表单、列表、内容延伸到栏位后、底部操作；输入时切换尺寸，检查遮挡及重复 inset |
| D07 | 转场与编辑保护 | push / pop、交互返回完成 / 取消、未保存编辑提示、sheet 打开 / 关闭；检查外观和状态恢复 |
| D08 | 无障碍与本地化 | 中文 / 英文 / RTL、辅助字号、VoiceOver；使用系统设置验证减少透明度、减少动态效果与提高对比度 |
| D09 | 多窗口 | 在支持的环境打开两个 Scene，分别选择标签、编辑文本和配置外观；确认相互独立 |
| D10 | 已有页面接入 | 使用 adapter 包装现有控制器，包含 `UITableViewController`；验证内容、安全区、导航和系统 sheet 协作 |
| D11 | 三处多媒体背景 | 页面 / 导航 / 标签分别选择图片、动图、MP4、HTML；比较预加载 / 清缓存切页，调整播放预算并连续切换资源 |
| D12 | 栏位字体与图标 | 设置导航 / 标签字号和颜色，对照普通 / 选中图标，切换资源图 / UIImage，恢复默认并验证输入与导航栈保留 |
| D13 | 栏位类型 | 对照系统与经典导航 / 标签，全宽底栏、安全区、输入保留、手势返回和整体背景协作 |

D01、D03 的系统原生基础路径，以及 D02 普通标题与少量按钮，为 0.1 必备；0.2 增加 D11 多媒体背景，0.3 增加 D12 栏位字体与图标。D02 多按钮、D04 原生分栏已有基础实现，D03 侧边栏、D09、多设备姿态与自定义浮动栏 / 完整 D05 按后续能力逐项验收。D06–D08、D10 从基础能力阶段逐步接入，并在对应能力声明完成前验收。未实现的场景标明状态，不展示模拟成功结果。

骨架 SDK 不强制依赖 BonePopoverKit。需要验证二者协作时，可增加单独的可选集成场景，复用现有主题与手势桥接。

## 3. 测试分层

| 层级 | 位置与框架 | 验证重点 |
| --- | --- | --- |
| SDK 单元测试 | `Tests/BoneShellKitTests/`；XCTest，覆盖最低运行版本 | 配置合并、显式恢复系统值、材质降级、按钮优先级与分组、背景缓存合并 / 失效、过期结果保护、播放预算 |
| Demo 集成测试 | `Examples/BoneShellDemo/Tests/`；XCTest | 公开接口接入真实 UIKit 容器，内容 guide、配置更新、控制器身份与生命周期 |
| Demo UI 测试 | `Examples/BoneShellDemo/UITests/`；XCTest / XCUITest | 点击、菜单、输入、导航、标签切换和状态恢复等用户行为 |
| 视觉与设备验收 | 模拟器截图及真机观察，必要时 Instruments | 原生玻璃 / 仿玻璃、实际重叠、对比度、Duo 姿态、动画连续性及性能 |

单元测试可以注入能力描述来验证解析规则，但这不等于在对应 OS 上运行。实际 availability、系统栏位行为和玻璃效果须在真实运行环境下验证。

UI 测试使用稳定 `accessibilityIdentifier` 和条件等待；针对用户可观察结果断言，不依赖系统私有视图类名、固定屏幕坐标或固定延时。原生栏位的玻璃视觉不能仅凭诊断标签判定通过。

## 5. 系统、设备与执行入口

| 运行环境 | 必测内容 |
| --- | --- |
| iOS 15 小屏 / 紧凑窗口 | 最低版本接入、旧版溢出、默认 / 仿玻璃、键盘及导航 |
| iOS 16 | 分组与系统 overflow 分支 |
| iPadOS 18 | 原生标签侧边栏分支与窄 / 宽窗口适配 |
| iOS / iPadOS 26 | 原生玻璃、经典模式、辅助设置与系统控件视觉 |
| iOS / iPadOS 27.1 | 当前高版本回归、Duo 各支持姿态及竖向栏位 |
| iPad 与 Duo 的动态窗口 | 选中详情和输入过程中 resize、展开 / 折叠及四边安全区 |

测试记录必须写实际 OS 版本、设备、尺寸、姿态和渲染器。缺少旧版 runtime 或某种设备时标为“未运行”，不能以新版系统上的能力注入测试替代。

Demo 工程建立后，提供共享的 `DemoSmoke.xctestplan` 与 `DemoRegression.xctestplan`，分别用于快速检查和完整行为回归；执行脚本分别运行 SDK 单元测试与 Demo 测试，避免误以为 Demo Scheme 自动包含全部 Package 测试。执行入口接受明确的模拟器 UDID，将 DerivedData、xcresult 和截图输出到指定临时 / 结果目录。

在真正创建工程后验证并记录可执行命令；当前不提供指向尚不存在工程的“已通过”运行记录。

## 6. 结果与交付标准

- 每项结果记录 SDK 修订、工具链、实际 OS / 设备、用例 ID、初始配置、实际渲染器 / 材质及通过 / 失败 / 未运行状态。
- 失败保留 xcresult、相关截图、断言与诊断原因。视觉基线按 OS、设备和配置区分；有意变更需说明依据，不能批量更新截图来掩盖回归。
- 自动化覆盖行为和状态；视觉、姿态与手势的设备验收分别留证，不能相互替代。
- 0.1 交付时，Demo 能从干净环境构建启动，基础场景与冒烟测试通过；每阶段新增能力同时补齐对应场景与测试。
- 1.0 发布前，所有声明支持的关键运行环境与用例均有记录；缺少的环境明确列入发布限制，不能写成已经支持并验证。

当前 Demo 与测试工程已经建立，0.2 增加背景与切页，0.3 增加栏位字体与图标，0.5 增加系统 / 经典类型场景；最新执行数量、截图和手机安装状态见 [验证记录](Implementation-Status.md)。规划用例数量与 XCTest 方法数量分别统计。完整场景矩阵仍按本规划逐步验收，不能将本轮通过结果扩展为全部设备 / 姿态已经通过。
